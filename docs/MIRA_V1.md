# KEIRIN LAB v1.0 — MIRA予測エンジン（実験版）

## 何が新しいか

- 競走得点・勝率・2連対率を使い、1着と2着を**異なる重み**で評価する2車単の確率モデルを追加
- 勝率・2連対率は割合（0～1）。競走得点はレース内で標準化する
- ラインの実証済み識別子がある場合のみ小さな相乗効果を仮定する。未確認ラインは補完しない
- 2車単全組み合わせを正規化して合計確率を1.0にする
- 本命／対抗／穴、保存時刻、判断根拠、モデル版を**上書き不可**で保存する
- 既存ベースラインと同一レースについて、的中率・上位3点率・対数損失・Brier・仮想回収率を比較
- 研究画面にモデル別比較と直近の予想一覧を追加する
- v0.8の日次出走表取り込み時、既存ベースラインに加え本モデルの予測も同時に凍結

**MIRAの「実験的ルールモデル」とチャットでMIRA本人が個別レースを分析して出す予想は異なります。** 本ロジックの係数は現時点で人手で設定した**未学習・未較正の仮説**。精度改善はまだ立証されていません。実レース蓄積後に時系列評価で判断します。

## 使用方法（クローン済みGitHubから）

~~~bash
git pull origin main
~~~

出走表登録と既存ベースラインの保存が済んだ、**発走前の実レース**について、書き込みなしで候補を確認する。

~~~bash
/usr/local/bin/python tools/mira_engine.py preview --race LIVE_202610211201
~~~

発走前に予測確率を固定する（1レースにつき一度だけ）。

~~~bash
/usr/local/bin/python tools/mira_engine.py freeze --race LIVE_202610211201
~~~

上記のレースIDは構造例。現在時刻より後に発走する実際の登録済みレースIDを使用してください。上記の2026年10月21日レースは発走後には新規予測できません。

保存済みモデル2種類があり、着順が確定したレースについてだけ比較できる。

~~~bash
/usr/local/bin/python tools/mira_engine.py report
/usr/local/bin/python tools/build_static.py
~~~

閲覧: `research.html` / `index.cgi?view=research`。CGI画面は読み取り専用。

v0.8からの自動取込を実行して許諾済みの出走表を登録すると、比較モデルと本MIRAルールモデルは同じ時間帯に予測を凍結する。外部リポジトリからの収集・保存には各取得元の再利用許可が必要。GitHubのリポジトリを更新しただけでは定期実行されない。

## モデル仕様

モデル版: `mira-rule-v1.0`。確率モデルはレース内の標準化された競走得点・勝率・2連対率に対する指数強度を計算し、1着の強度と2着の条件付き強度から2車単組み合わせ確率を作る。ラインへの加点は確認済みの共通`line_id`のみ。係数の変更では**モデル版の更新**が必須。

データベースの追加テーブル:

- `mira_rule_forecasts` : 車番順序別2車単の全確率、版、スナップショット
- `mira_rule_decisions` : 本命・対抗・穴、根拠、版、時刻

両テーブルは `src/keirinlab/mira_engine.py` が初回の予測保存時に作成する。旧DBを削除・移行し直す必要はありません。

## 評価上の制限

- 必ず実レースかつ**発走前の出走表情報**があること
- 出走表の観測時刻が両モデルの保存時刻より前であること
- 2車単の確率が全候補を網羅し総和1となること
- 確定した着順と払戻が必要で、払戻不明のときは回収率に算入しない
- 各評価指標の対象は**2モデルとも正常な予測が保存されている同じレース**に限定
- 元のモデル予測、MIRAモデル予測、MIRAチャットによる人手作成予想を別々に計測する
- 勝率や回収率の高低を少数サンプルで決めない。今後は信頼区間・時系列ウォークフォワードで評価する
